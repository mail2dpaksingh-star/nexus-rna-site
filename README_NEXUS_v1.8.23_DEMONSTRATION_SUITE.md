# NEXUS RNA BioSolutions v1.8.23 — Experimental Data Demonstration & Validation Suite

## Summary

Built on v1.8.22. All ThermoFold code and previous scientific engines remain unchanged. The new page is:

`tools/construct-studio/demo/index.html`

The latest site navigation links to it from the homepage's illustrative project, Construct Studio, Evidence Workbench, and Project Hub. This is **not** an instrument-qualified or GMP system.

## What is included

- An interactive, browser-only example of **three fictional RNA construct versions**, labeled A, B, C.
- Two fictional cell-model labels (**A549** and **HEK293**), 3 fictional biological replicates per construct/cell label, and 2 fictional technical wells per replicate.
- A separate synthetic RNA-signal decay exercise; its one-biological-replicate series is not an experimental RNA half-life estimate.
- Explicit identities for each of **27 fictional samples**, **54 synthetic measured entries** in the linked evidence data, and 5 independent synthetic CSV import fixtures (**126 exported rows altogether**).
- Five synthetic vendor-style fixtures: QuantStudio-style qPCR, Bio-Rad-style ddPCR, Gen5-style plate reader, FlowJo-style summary, and Bioanalyzer-style peak tables. **These were generated by NEXUS, not by the vendors or physical instruments**.
- SHA-256 file manifest, reproducible Node fixture generator and independent test suite.
- A comparison page showing the exact existing NEXUS biological-replicate summary and matched-comparison engine outputs.
- Downloadable analysis CSV and JSON. The demo can be copied to a separate, unmistakably labeled, browser-local project **only after user confirmation**, with no overwriting of an existing project or automatic cloud synchronization.

## How to use

1. Extract the **entire website** package, upload its contents to the GitHub repository connected to Cloudflare Pages, and deploy as usual.
2. Open `/tools/construct-studio/demo/index.html`.
3. Toggle A549 / HEK293 and look at descriptive construct measurements.
4. Select `Synthetic RNA-signal decay` for the separate *A549-only* illustrative time-course; the half-life output must not be presented as biological evidence.
5. Download the practice qPCR/ddPCR/plate/flow/Bioanalyzer CSVs.
6. Click `Create separate demo project`, confirm, then open `Construct-to-Evidence Workbench` → `Native instrument export integration`.
7. Select an appropriate vendor-style fixture, check the column mapping, manually verify sample mapping, supply units and the **distinct run ID**, preview, and import. The demonstration project contains nonconfidential synthetic data only.

When importing a fixture for each assay, choose units appropriate to the specific exported numeric column. A Cq number is **not** directly an RNA fold-change, and Bioanalyzer peak-area data are **not** protein-expression data. Retain original files outside of browser-local records for traceability.

## Scientific boundaries

**Every nucleotide sequence, numerical result and sample identifier in the demo is fabricated.** The differences between RNA candidates are **deliberately assigned**, not predicted by an RNA algorithm, and not obtained from cells or instruments. The fixture is useful only for UI, data-model, data-integrity, and arithmetic testing. No empirical RNA stability, drug efficacy, regulatory performance, instrument compatibility or method qualification is established. Do not mix demo data with laboratory observations.

The site links to the [RDML standard](https://rdml.org/) and [FlowRepository](https://flowrepository.org/) as possible public external-data starting points; no public experiment is bundled or presented as part of the fictional comparison. Real vendor qualification still requires genuine de-identified exports matched to the exact software version and instrument method.

## Development checks

Run from the extracted site root:

```bash
node tools/construct-studio/demo/generate-demo.js
node tests/test-demo-v1823.js
```

The generator overwrites only files in `tools/construct-studio/demo/fixtures/` and is entirely deterministic. The five fixture SHA-256 checksums are recorded in `manifest.json`. The test checks all five adapters, 126 rows, baseline comparisons, sample mapping rejection, and duplicate import rejection.

In this environment, desktop and mobile interactions were tested with isolated HTML/JavaScript content. The public-hosted route and Supabase login were **not** tested. Supabase configuration is still optional and not part of the demo.
